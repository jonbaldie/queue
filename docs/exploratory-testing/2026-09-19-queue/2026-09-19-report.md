# Queue exploratory-testing report — 2026-09-19

## Outcome

Three confirmed bugs, all filed:

| Issue | Journey | Impact |
| --- | --- | --- |
| [#114](https://github.com/jonbaldie/queue/issues/114) | Docker persistence | The README's `--persist` Docker command exits immediately with `PermissionDenied` because `/mnt` is root-owned and the image runs as `deno`. Mounting a volume at `/mnt` fails too. |
| [#115](https://github.com/jonbaldie/queue/issues/115) | Durability | `persist.dat` is truncated and then rewritten in place on every start and every graceful shutdown. A kill inside that window permanently loses every acknowledged item (3/3 on startup, 2/2 on shutdown). |
| [#116](https://github.com/jonbaldie/queue/issues/116) | Payload fidelity | Invalid UTF-8 inside a JSON string is silently replaced with U+FFFD and acknowledged with `200`. |

No candidates remain unresolved.

## Setup and evidence

- Build: `main` at `e0d2108`, Deno 2.7.6 (aarch64-apple-darwin), Docker Desktop (linux/arm64).
- Docker image built locally: `docker build -t queue-explore:e0d2108 .`
- Executable path: `deno run --allow-all main.ts`, with a fresh temp `PERSIST` directory for every persistence run.
- Everything was driven through the public HTTP API with `curl`, `fetch`, and `docker`, with no mocks. Signals were delivered to real processes and containers.
- Evidence directory: this folder.
  - [docker-persist-readme.txt](./docker-persist-readme.txt): the README command, with a repeat run
  - [docker-persist-variations.txt](./docker-persist-variations.txt): published image, a volume at `/mnt`, a volume at `/queue/data`
  - [docker-persist-workaround.txt](./docker-persist-workaround.txt): control run with `PERSIST` unset
  - [snapshot-kill-replay.ts](./snapshot-kill-replay.ts): replay driver for #115 (`MODE=shutdown` covers the shutdown path)
  - [snapshot-kill-replay.txt](./snapshot-kill-replay.txt) and [snapshot-kill-shutdown-replay.txt](./snapshot-kill-shutdown-replay.txt)

This pass picked areas those passes had not touched: Docker as the documented deployment surface, what happens when a kill lands during the snapshot rewrite, and how request bodies are encoded.

## Journeys

### 1. Run the Docker image with persistence as the README documents

Goal: a container that keeps queued items across `docker stop`/`start`, stored at `PERSIST=/mnt/`, optionally on a volume.

- Ordinary path: the README command, run verbatim apart from the image tag and host port. **Failed.** The container reached `Exited (1)` with `PermissionDenied ... open '/mnt/persist.dat'`. It failed again from a fresh container. → #114
- Variation, named volume at `/mnt` as the README suggests: same failure. A volume at `/queue/data` with `PERSIST=/queue/data/` also failed, because Docker creates a volume at a missing path owned by root.
- Variation, published `jonbaldie/queue:latest`: that image was built 2022-08-15 and is amd64 only. It also exits on the README command, with `NotFound`.
- Control (intervention: `PERSIST` unset, so it defaults to `WORKDIR /queue`, owned by `deno`): enqueued `one two three`, dequeued `one`, ran `docker stop`/`start`, and got `length 2`, then `two`. Enqueued `four`, ran `docker kill`/`start`, and got `three`, `four`, then `204`. The persistence logic works. The broken part is the path the README documents.

### 2. Durable backlog through restarts

Goal: every item acknowledged with `200` under `--persist` survives any process death.

- Ordinary path, repeated from earlier passes: SIGKILL followed by a normal restart recovers all items.
- Variation: a kill while the startup snapshot rewrite is running. The server replays the log, calls `save()` (`truncateSync(0)` then `saveBatch`), and was SIGKILLed once the file had shrunk. **200 of 200 acknowledged items were lost on 3 of 3 runs**, and the next start came up healthy with an empty queue. → #115
- Variation: SIGTERM followed by SIGKILL during the shutdown flush, which matches Docker/Kubernetes escalating after the grace period. 199 of 200 and then 200 of 200 items were lost across 2 runs.
- Window size, measured with a 200 MB log: about 2 s on startup and about 100 ms on shutdown. It grows with the backlog.

### 3. Payload fidelity for non-UTF-8 producers

Goal: what a consumer dequeues is exactly what the producer enqueued, or the enqueue is rejected.

- Ordinary path: UTF-8 `café` round-trips correctly.
- Variation: Latin-1 `caf\xe9` returned `200` and dequeued as `"caf�"`. The truncated sequence `a\x80b\xe2\x82` returned `200` and dequeued as `"a�b�"`. The same kind of bytes outside a string returned `400 Invalid JSON`. Results were the same on each replay. → #116

## Rejected candidates

- Local `docker build` copies the developer's `persist.dat` into `/queue` because `.dockerignore` doesn't list it. The file is git-ignored, and in this checkout it was 0 bytes, so a clean-checkout build is unaffected. Kept as an observation, not a bug.
- `X-Forwarded-For` is ignored by the rate limiter whenever a TCP peer address exists, so every client behind a reverse proxy shares one bucket. This is a design choice the docs don't contradict, so no bug was filed.

## Usability observations

- Observation: nothing in `.github/workflows/ci.yml` publishes the Docker image, and `jonbaldie/queue:latest` on Docker Hub dates from 2022. The README's `docker run ... jonbaldie/queue` therefore runs code from before `QUEUE_API_TOKEN` existed. Suggestion: publish images from CI, or tell users to build locally.
- Observation: the published image is amd64 only, and on Apple Silicon Docker prints a platform warning.
- Observation: `--persist` failures surface as uncaught Deno stack traces with ANSI colour codes in `docker logs`. Suggestion: catch the error at startup and print one line naming `PERSIST` and the path.

## Limitations and unexplored areas

- Disk-full in the middle of `saveBatch` was not reproduced. It is the same code path as #115 and was not needed to confirm it.
- The compiled binary was only exercised inside the Docker image, not on the host.
- Behaviour on Linux host filesystems (fsync and rename semantics) was not tested separately. Every kill test ran on macOS APFS.

## Cleanup

All `qx-*` containers and volumes were removed, and every temp `PERSIST` directory was deleted by the replay script. The local image `queue-explore:e0d2108` was removed at the end of the pass.
